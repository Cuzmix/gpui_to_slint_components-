# Porting gaps

Every place where the Slint port cannot reproduce the GPUI original exactly. Each row: the GPUI behavior, the Slint limitation, the workaround, and the difference that remains on screen.

| # | Component | GPUI behavior | Slint limitation | Workaround | Remaining visible difference |
|---|---|---|---|---|---|
| G1 | Theme | Changing mode, high contrast, color-blind charts or a custom palette cross-fades every color over 280 ms (ease-in-out-cubic), driven by the app. | A `global` cannot hold `animate`, `states` or a `Timer`. | `ThemeFader` component placed once per window runs the 8 ms frame timer and writes `Theme.fade`; `Theme.colors` blends `fade-from` → `fade-to`. | None when a `ThemeFader` is in the window. Without one, changes apply at once. Removing the fader mid-fade leaves the blend where it stopped. |
| G2 | Theme | Colors blend in 32-bit float sRGB. | Slint colors are 8 bits per channel; Slint's own `mix` is SASS-style and differs when alphas differ. | `Palettes.mix` reimplements GPUI's straight per-channel lerp. | Up to 1/255 per channel from 8-bit rounding. |
| G3 | Elevation (Tooltip, later menus, dialogs) | Two `BoxShadow` layers per level. | One drop shadow per element. | `Elevated` stacks a same-size child carrying the second layer. | Layers match; gpui's blur kernel and Slint's `drop-shadow-blur` may not fall off identically, so the shadow edge can look slightly softer or harder. Not measured against a GPUI capture yet. |
| G4 | Theme | `platform` starts as the build's OS. | Slint has no compile-time OS query in `.slint`. | Defaults to `linux`; the host sets `Theme.platform` (the Rust crate's `Platform::current()` gives the value). | On macOS and Windows, platform-specific drawing (key caps, window buttons) is Linux-style until the host sets it. |
| G5 | Spinner | Arcs are polylines of 32 segments per full turn. | None; Slint draws true arcs. | `Path` with `ArcTo`. | The ring is slightly smoother than GPUI's 32-segment polygon. |
| G6 | Tooltip | gpui shows tooltips from its own hover tracking on any element, including on touch long press. | Slint has no tooltip hook; a nested TouchArea would steal the host's clicks. | `TooltipController` is fed the host TouchArea's pointer events (`pointer-event`, `dismiss`). | Touch long-press tooltips are not implemented. |
| G7 | Tooltip | Flips left or up when it would leave the window (`prepaint_tooltip`). | A `PopupWindow` cannot read its absolute position or the window size from inside, before it is shown. | None yet; Slint keeps popups inside the window on its own. | Near the right or bottom edge the tip is pushed inside instead of flipping to the other side of the pointer. Not yet verified on every backend. |
| G8 | Button | `shortcut("secondary-s")` parses gpui key syntax and spells it per platform. | `.slint` has no string splitting. | `Button.shortcut` takes the spelled text; `ely_slint::shortcut_text` ports gpui's parser and Ely's key caps exactly. | None when the host uses the Rust helper. Pure-Slint users type the caps themselves. |
| G9 | Button (link) | Hover underlines the label with gpui's text underline. | Slint 1.18 `Text` has no underline. | A 1 px rectangle in the label color under the text. | The underline's distance from the baseline is estimated from the font size, so it can sit a pixel or two off. |
| G10 | IconButton | Without a tooltip, the accessible name is the icon's Lucide name. | A Slint `image` does not carry its file name. | `icon-name` property; `CloseButton`, `BackButton`, `MoreButton` set it. | None if the owner sets `icon-name` or `tooltip`; otherwise the button has no accessible name. |
| G11 | Button, IconButton | `disabled(bool)`. | None; naming only. | Slint's idiomatic `enabled` (inverse). | None. |
